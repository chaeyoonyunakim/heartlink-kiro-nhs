# Requirements Document

## Introduction

This feature delivers HeartLink — a reproducible, end-to-end machine learning pipeline for heart disease analysis using the UCI Heart Disease dataset. The pipeline reads raw patient data from a CSV file, preprocesses it with clinical guardrails to handle medical noise, and addresses three complementary problem types: (1) binary classification to predict heart disease presence, (2) regression to quantify cardiac functional decline by predicting maximum heart rate, and (3) clustering to discover patient risk groups without diagnostic labels. The priority is a fully working, reproducible solution over maximum accuracy. The guiding principle is that preprocessing quality and data integrity matter more than algorithmic complexity — in medical AI, ensuring data integrity is as vital as domain expertise.

## Success Criteria

A successful HeartLink prototype meaningfully reduces the cognitive load of the clinical team — not by making autonomous medical decisions, but by surfacing critical diagnostic insights at the point of care.

1. **Live Patient Case Walkthrough**: The pipeline can process a patient case and surface relevant clinical context alongside the data, including flagging biologically impossible noise (e.g., 0 cholesterol) whilst cross-referencing data quality standards.

2. **Actionable Risk Stratification**: The system can show exactly where a patient sits within their risk cluster (e.g., Cluster 3: Potential Risk) and what specific action is required, such as lifestyle intervention or a specialised referral.

3. **Transparent Architecture**: The prototype clearly distinguishes which insights are generated by the validated Random Forest classification model and which recommendations are powered by agentic LLM reasoning. This transparency ensures the tool remains a reliable, spec-driven assistant.

4. **Workforce Alignment**: The system's outputs support the wider Ten Year Health Workforce Plan by enabling routine screening to shift to primary care or pharmacy settings, freeing specialist capacity for complex cases.

## Glossary

- **Pipeline**: The complete Python script that executes all steps from data loading through evaluation in a single run
- **Dataset**: The UCI Heart Disease CSV file located at `data/heart_disease_uci.csv` containing 920 patient records from four research studies (Cleveland, Hungary, Switzerland, VA Long Beach)

### Heart Disease Dataset Schema

- **id**: unique identifier for each patient
- **age**: age of the patient in years
- **sex**: Male/Female
- **dataset**: place of study (data drawn from four studies)
- **cp**: chest pain type (typical angina, atypical angina, non-anginal, asymptomatic)
- **trestbps**: resting blood pressure in mmHg on admission to hospital
- **chol**: serum cholesterol in mg/dl
- **fbs**: fasting blood sugar > 120 mg/dl (True / False)
- **restecg**: resting electrocardiographic results (normal, ST-T abnormality, LV hypertrophy)
- **thalch**: maximum heart rate achieved
- **exang**: exercise-induced angina (True / False)
- **oldpeak**: ST depression induced by exercise relative to rest
- **slope**: the slope of the peak exercise ST segment (upsloping, flat, downsloping)
- **ca**: number of major vessels (0–3) coloured by fluoroscopy
- **thal**: a blood disorder called thalassaemia (normal, fixed defect, reversible defect)
- **num**: heart disease indicator (0 to 4, with 0 indicating absence)

### Domain Terms

- **Target_Variable**: A binary label derived from the `num` column where 0 indicates no heart disease and 1 indicates heart disease present (original values 1–4 collapsed to 1)
- **Numerical_Feature**: A column in the Dataset with continuous or integer values requiring median imputation: age, trestbps, chol, thalch, oldpeak. Note: `ca` is also numeric (integer 0–3) and included in modelling features but handled separately as it has discrete values
- **Categorical_Feature**: A column in the Dataset with discrete, non-numeric values requiring mode imputation: sex, cp, fbs, restecg, exang, slope, thal
- **Biologically_Impossible_Value**: A recorded measurement of zero for a vital sign or laboratory result where zero is clinically impossible in a living patient; specifically `trestbps` = 0 mmHg (1 known case) and `chol` = 0 mg/dl (172 known cases)
- **Preprocessing**: The set of transformations applied to raw data before model training, including clinical guardrail checks, missing value handling, encoding, and scaling
- **Classification_Model**: A scikit-learn estimator trained to predict the Target_Variable from preprocessed features
- **Regression_Model**: A scikit-learn estimator trained to predict `thalch` (maximum heart rate) from patient features to quantify cardiac functional decline
- **Regression_Features**: The subset of features used as predictors for the Regression_Model: age, trestbps, chol
- **Regression_Target**: The `thalch` column used as the continuous target variable for the Regression_Model
- **Regression_Preprocessing**: A systematic preprocessing strategy for the regression task that tests 8 dataset variants across three controlled dimensions: hospital inclusion (all hospitals vs Cleveland-only), imputation method ("Unknown" category vs mean/mode), and outlier removal (with vs without IQR-based outlier filtering)
- **Dataset_Variant**: One of 8 combinations of preprocessing choices tested during regression to identify the optimal data preparation strategy
- **Clustering_Model**: An unsupervised scikit-learn estimator (KMeans) that groups patients based on data patterns without using diagnostic labels. KMeans was selected over DBSCAN due to DBSCAN producing excessive noise points or tiny clusters on complex medical data, making KMeans more interpretable for clinical use
- **Clustering_Preprocessing**: A stricter data cleaning pipeline applied specifically to clustering that excludes high-missingness variables (ca, thal, slope) to prevent hospital bias, removes samples with >30% missing values, and imputes cholesterol using sex-and-age-group medians
- **Hospital_Bias**: A data quality concern where missingness in certain variables (ca, thal, slope) is concentrated in specific data sources (all except Cleveland), meaning their absence reflects collection practices rather than clinical reality
- **Evaluation_Metrics**: Quantitative measures of model performance including accuracy, precision, recall, F1-score, and AUC-ROC for classification; MAE, RMSE, and R² for regression; silhouette score and cluster distribution for clustering
- **EDA_Report**: Exploratory data analysis outputs including summary statistics, distribution plots, and correlation analysis
- **Train_Test_Split**: The partitioning of the Dataset into training and testing subsets using a fixed random seed

## Users

### The Patient
An individual presenting with chest pain who requires an early diagnosis to improve their clinical survival odds. They are often accessing screening information via a mobile device whilst under extreme time pressure and high anxiety about their cardiac health. They need immediate confidence that HeartLink has validated their vitals accurately and that their risk profile is being processed to provide clear, personalised next steps.

### The Clinician (GP or Hospital Doctor)
The frontline user who receives patient data and must make life-critical triage decisions. They are frequently burdened by "medical noise," such as biologically impossible zero-values for blood pressure or cholesterol, and incomplete records regarding major vessels. They currently spend valuable time manually identifying data inconsistencies that HeartLink is designed to automate.

### The Clinical Lead or Service Owner
Responsible for a diagnostic pathway that currently suffers from screening backlogs, patient complaints, and avoidable contact. They recognise that static, paper-based, or manual triage approaches are no longer effective but lack the internal technical capacity to implement AI guardrails. They require a "Spec-First" agentic framework like HeartLink to ensure any new diagnostic tool is reproducible, traceable, and meets NHS engineering excellence standards.

### The Cardiac Radiographer or Diagnostic Technician
A specialist responsible for high-fidelity testing, such as fluoroscopy to determine the number of major vessels (ca) or monitoring the ST segment during exercise (oldpeak). They are the primary source of the model's most medically important features. They face challenges with equipment noise or patient fatigue that leads to missing data in critical fields like ca or thal. They need HeartLink's guardrails to provide real-time feedback on data quality, ensuring that a "zero" entry is a true clinical finding and not a recording error.

### The Community Pharmacist
Working in a high-street primary care setting, they are often the first point of contact for patients seeking preventative health checks. They deal with high-volume, walk-in consultations where time is a luxury. They encounter patients who may fall into the "Potential Risk" cluster group — characterised by high blood pressure and cholesterol but not yet symptomatic. They need a tool that can quickly ingest vital signs and provide clear, evidence-based guidance to help them decide whether to offer lifestyle advice or trigger an urgent GP referral.

### The Workforce, Training and Education Planning Leader (NHS England)
Responsible for implementing the Ten Year Health Workforce Plan, they must ensure the long-term sustainability of the cardiac care pathway. They oversee a workforce under immense pressure, where specialists are often bogged down by manual triage and low-value data entry tasks. They need HeartLink to optimise the workforce by shifting routine screening to primary care or pharmacy settings. They also require the system's performance reports to identify specific regional training needs — such as improving the accuracy of complex fluoroscopy inputs (ca) or ST-segment monitoring — to reduce data missingness and hospital bias.

## Requirements

### Requirement 1: Data Loading

**User Story:** As a data scientist, I want to load the UCI heart disease CSV file into a structured format, so that I can begin analysis and modelling.

#### Acceptance Criteria

1. WHEN the Pipeline is executed, THE Pipeline SHALL read the file at `data/heart_disease_uci.csv` into a pandas DataFrame
2. WHEN the Dataset is loaded, THE Pipeline SHALL verify that the DataFrame contains exactly 16 columns: id, age, sex, dataset, cp, trestbps, chol, fbs, restecg, thalch, exang, oldpeak, slope, ca, thal, num
3. WHEN the Dataset is loaded, THE Pipeline SHALL print the shape of the DataFrame and the first 5 rows to standard output
4. IF the CSV file is not found at the expected path, THEN THE Pipeline SHALL raise a FileNotFoundError with a message indicating the expected file path

### Requirement 2: Target Variable Creation

**User Story:** As a data scientist, I want to binarise the `num` column into a binary target, so that I can frame the problem as binary classification.

#### Acceptance Criteria

1. WHEN the Dataset is loaded, THE Pipeline SHALL create the Target_Variable by mapping `num` value 0 to 0 and `num` values 1, 2, 3, and 4 to 1
2. WHEN the Target_Variable is created, THE Pipeline SHALL print the class distribution (count of 0s and 1s) to standard output
3. WHEN the Target_Variable is created, THE Pipeline SHALL drop the original `num` column from the feature set
4. FOR ALL rows in the Dataset, binarising the Target_Variable and then checking that each value is in {0, 1} SHALL confirm the transformation is valid (round-trip property: every original `num` value maps to exactly one binary class)

### Requirement 3: Exploratory Data Analysis

**User Story:** As a data scientist, I want to explore the dataset's distributions and relationships, so that I can understand the data before modelling.

#### Acceptance Criteria

1. WHEN the Dataset is loaded, THE Pipeline SHALL generate summary statistics (count, mean, std, min, max, quartiles) for all Numerical_Features
2. WHEN the Dataset is loaded, THE Pipeline SHALL generate a count of missing values per column and print the result to standard output
3. WHEN the Dataset is loaded, THE Pipeline SHALL save a correlation heatmap of Numerical_Features as a PNG file in the `outputs/` directory
4. WHEN the Dataset is loaded, THE Pipeline SHALL save a bar chart showing the Target_Variable class distribution as a PNG file in the `outputs/` directory
5. WHEN the Dataset is loaded, THE Pipeline SHALL save distribution histograms for each Numerical_Feature as PNG files in the `outputs/` directory
6. WHEN the Dataset is loaded, THE Pipeline SHALL save boxplots for each Numerical_Feature categorised by sex and Target_Variable as PNG files in the `outputs/` directory to visualise outliers and distribution skewness that justify the choice of median over mean imputation

### Requirement 4: Data Preprocessing

**User Story:** As a data scientist, I want to preprocess the raw data into a model-ready format, so that all three models (classification, regression, clustering) can train on clean, encoded features.

#### Acceptance Criteria

1. WHEN preprocessing begins, THE Pipeline SHALL drop the `id` and `dataset` columns from the feature set since they are identifiers and not predictive features
2. WHEN preprocessing begins, THE Pipeline SHALL replace Biologically_Impossible_Values (zero values in `trestbps` and `chol`) with NaN so they are treated as missing data rather than valid measurements
3. WHEN the Pipeline replaces Biologically_Impossible_Values, THE Pipeline SHALL print the count of replaced zeroes per column to standard output
4. WHEN missing values are detected in Numerical_Features (age, trestbps, chol, thalch, oldpeak), THE Pipeline SHALL impute them using the median value of the respective column, as outliers and skewed distributions make mean imputation unreliable
5. WHEN missing values are detected in Categorical_Features (sex, cp, restecg, exang, slope, thal), THE Pipeline SHALL impute them using the mode (most frequent value) of the respective column
6. WHEN Categorical_Features are preprocessed, THE Pipeline SHALL encode them using one-hot encoding with the first category dropped to avoid multicollinearity
7. WHEN Numerical_Features are preprocessed, THE Pipeline SHALL scale them using standardisation (zero mean, unit variance)
8. THE Pipeline SHALL construct a scikit-learn ColumnTransformer that applies the appropriate transformations to Numerical_Features and Categorical_Features in a single step

### Requirement 5: Train-Test Split

**User Story:** As a data scientist, I want to split the data into training and testing sets with a fixed seed, so that results are reproducible.

#### Acceptance Criteria

1. WHEN the preprocessed data is ready, THE Pipeline SHALL split the Dataset into 80% training and 20% testing subsets
2. THE Pipeline SHALL use a fixed random seed of 42 for the Train_Test_Split to ensure reproducibility
3. WHEN the Train_Test_Split is performed, THE Pipeline SHALL use stratified sampling based on the Target_Variable to preserve class proportions in both subsets
4. WHEN the Train_Test_Split is complete, THE Pipeline SHALL print the number of samples in the training set and the testing set to standard output

### Requirement 6: Model Training

**User Story:** As a data scientist, I want to train a classification model on the preprocessed training data, so that I can predict heart disease presence.

#### Acceptance Criteria

1. THE Pipeline SHALL train a single Classification_Model using the scikit-learn Random Forest classifier
2. WHEN the Classification_Model is trained, THE Pipeline SHALL use a fixed random seed of 42 for the classifier to ensure reproducibility
3. WHEN the Classification_Model is trained, THE Pipeline SHALL fit the model on the training subset produced by the Train_Test_Split

### Requirement 7: Model Evaluation

**User Story:** As a data scientist, I want to evaluate the trained model with standard metrics, so that I can assess its predictive power.

#### Acceptance Criteria

1. WHEN the Classification_Model is trained, THE Pipeline SHALL generate predictions on the testing subset
2. WHEN predictions are generated, THE Pipeline SHALL compute and print accuracy, precision, recall, and F1-score to standard output
3. WHEN predictions are generated, THE Pipeline SHALL compute and print the AUC-ROC score to standard output
4. WHEN predictions are generated, THE Pipeline SHALL save a confusion matrix visualisation as a PNG file in the `outputs/` directory
5. WHEN predictions are generated, THE Pipeline SHALL save a ROC curve plot as a PNG file in the `outputs/` directory
6. WHEN evaluation is complete, THE Pipeline SHALL save a classification report as a text file in the `outputs/` directory

### Requirement 8: Regression Model — Predicting Maximum Heart Rate

**User Story:** As a data scientist, I want to build a regression model predicting maximum heart rate using systematically tested dataset variants, so that I can quantify cardiac functional decline whilst controlling for source bias, imputation method, and outlier effects.

#### Acceptance Criteria — Dataset Variant Generation

1. THE Pipeline SHALL generate 8 Dataset_Variants by combining three binary preprocessing dimensions:
   - **Hospital inclusion**: (a) all four hospitals, (b) Cleveland-only
   - **Imputation method**: (a) "Unknown" category for missing categoricals + median for numericals, (b) mean for numericals + mode for categoricals
   - **Outlier removal**: (a) retain all data, (b) remove outliers using IQR-based filtering (1.5× IQR beyond Q1/Q3) on Numerical_Features
2. WHEN generating each Dataset_Variant, THE Pipeline SHALL replace Biologically_Impossible_Values (zero values in `trestbps` and `chol`) with NaN before applying the variant's imputation method
3. WHEN generating each Dataset_Variant, THE Pipeline SHALL print the variant label, sample count, and feature count to standard output

#### Acceptance Criteria — Model Training and Selection

4. FOR EACH of the 8 Dataset_Variants, THE Pipeline SHALL extract the Regression_Features (age, trestbps, chol) and the Regression_Target (thalch), excluding rows with NaN in those columns after variant-specific preprocessing
5. FOR EACH Dataset_Variant, THE Pipeline SHALL split the data into 80% training and 20% testing subsets using a fixed random seed of 42
6. FOR EACH Dataset_Variant, THE Pipeline SHALL train a Regression_Model using scikit-learn Linear Regression on the training subset
7. FOR EACH Dataset_Variant, THE Pipeline SHALL compute Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), and R² score on the testing subset
8. WHEN all 8 variants are evaluated, THE Pipeline SHALL print a comparison table of all variants with their MAE, RMSE, and R² scores to standard output
9. WHEN all 8 variants are evaluated, THE Pipeline SHALL select the best-performing variant based on the highest R² score and print the selected variant label

#### Acceptance Criteria — Best Model Evaluation Outputs

10. WHEN the best variant is selected, THE Pipeline SHALL save a scatter plot of predicted vs actual `thalch` values for the best variant as a PNG file in the `outputs/` directory
11. WHEN the best variant is selected, THE Pipeline SHALL save a residual plot for the best variant as a PNG file in the `outputs/` directory
12. WHEN the best variant is selected, THE Pipeline SHALL save the variant comparison table as a CSV file in the `outputs/` directory

### Requirement 9: Clustering — Patient Risk Group Discovery

**User Story:** As a data scientist, I want to cluster patients based on their clinical attributes without using diagnostic labels, so that I can explore potential high-risk groups.

#### Acceptance Criteria — Clustering-Specific Preprocessing

1. WHEN preparing data for clustering, THE Pipeline SHALL exclude variables with excessive missing rates (ca, thal, slope) to prevent Hospital_Bias, as missingness in these columns is concentrated in non-Cleveland data sources
2. WHEN preparing data for clustering, THE Pipeline SHALL remove samples with more than 30% missing values across remaining features and print the number of samples removed (expected reduction from 920 to approximately 865 samples)
3. WHEN preparing data for clustering, THE Pipeline SHALL impute `chol` values (including Biologically_Impossible_Values replaced with NaN) using sex-and-age-group medians to reflect medical trends where cholesterol levels vary by sex and age bracket
4. WHEN preparing data for clustering, THE Pipeline SHALL impute remaining missing Numerical_Features using the column median and remaining missing Categorical_Features using the column mode
5. WHEN preparing data for clustering, THE Pipeline SHALL encode Categorical_Features using one-hot encoding and scale all features using standardisation

#### Acceptance Criteria — Dimensionality Reduction

6. WHEN clustering features are preprocessed, THE Pipeline SHALL apply PCA with n_components=0.9 to reduce dimensionality whilst preserving at least 90% of the variance
7. WHEN PCA is applied, THE Pipeline SHALL print the number of components retained and the cumulative explained variance ratio to standard output

#### Acceptance Criteria — Model Training and Evaluation

8. THE Pipeline SHALL train a Clustering_Model using scikit-learn KMeans with a fixed random seed of 42
9. WHEN selecting the number of clusters, THE Pipeline SHALL evaluate k values from 2 to 8 using the silhouette score and select the k with the highest silhouette score
10. WHEN the Clustering_Model is trained with the optimal k, THE Pipeline SHALL print the silhouette score and the patient count per cluster to standard output
11. WHEN the Clustering_Model is trained, THE Pipeline SHALL save an elbow plot (inertia vs k) as a PNG file in the `outputs/` directory
12. WHEN the Clustering_Model is trained, THE Pipeline SHALL save a 2D scatter plot of the clusters (using the first two principal components from PCA) as a PNG file in the `outputs/` directory
13. WHEN the Clustering_Model is trained, THE Pipeline SHALL print a summary table showing the mean values of each feature per cluster to standard output

### Requirement 10: End-to-End Reproducibility

**User Story:** As a data scientist, I want the entire pipeline to be executable in a single command, so that anyone can reproduce the results from CSV to outputs.

#### Acceptance Criteria

1. THE Pipeline SHALL be executable end-to-end by running `python src/pipeline.py` from the project root
2. THE Pipeline SHALL create the `outputs/` directory if the directory does not already exist
3. THE Pipeline SHALL set a global random seed of 42 at the start of execution to ensure reproducibility across all operations
4. WHEN the Pipeline completes, THE Pipeline SHALL print a summary message listing all output files generated
5. FOR ALL executions of the Pipeline with the same input CSV and random seed, the Pipeline SHALL produce identical Evaluation_Metrics for classification, regression, and clustering (idempotence property: repeated runs yield the same results)
